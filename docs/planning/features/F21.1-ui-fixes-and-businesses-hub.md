### US-265 UI fixes

As the player, I want the HUD and sheets to look right, so that nothing is cut, wrapped or pointless on screen.

- **Points:** 3 · **Priority:** Must · **Sprint:** S28
- **Acceptance:** Spec 030 AC-1 to AC-3

**Tasks**

- [x] US-265.T1 Collect all hidden at 0 (`HudPresenter`, `HudVm.ShowCollect`); the alerts bell drops to the corner when it is hidden; `HudViewTests.CollectHidden`
- [x] US-265.T2 Tab rows scroll sideways with edge fades, the showing tab scrolled into view (`SheetPresenter.TabStrip`); the sheet's vertical scroll is now found by name (`sheetScroll`), as `TouchDriver.ScrollOffset`
- [x] US-265.T3 Badges as circle or pill, no wrap, "99+" (People, Orders, alerts; `UiKit.FitBadge`); `HudViewTests.BadgeText`
- [x] US-265.T4 Editor overflow check over every sheet the town can reach (`Game.Editor.SheetLayoutCheck`: 74 sheets in a Village town, 0 problems after fixes). It found, and the story fixed: the Savings sheet's last row pushed its ? off the sheet, and the crop calendar's "Fodder sorghum" ran past its column
- [x] US-265.T5 Editor tour by scripted touch, captures looked at (`docs/art/s28-265-*.png`), `RenderStats` at all three views (none over 10%: all 1,184 draw calls / 23,758 triangles, village 546 / 11,117, farm 339 / 6,600)

**Learned:** the People badge showed "1" with a stray "1" beside the button because the badge label is made empty and `UiKit.Text` then leaves it wrapping inside a 54-unit circle. A `ScrollView` placed before the sheet's own scroll was found first by `Q<ScrollView>()`, so the sheet scroll is named. A `ScrollView`'s content container reports the viewport's width however far its content runs: the fades read the scroller's `highValue`.
